# 阶段 5：集成、性能与交付验收

前置：阶段 4 通过。遵守 [共同约束](README.md) 和 [完整契约](../AUTOMATION_PLAN.md)。

## 范围

验证完整闭环、故障恢复、旧功能兼容和历史增长；修复当前自动化变更造成的问题，完成用户文档。不得借验收扩展后台服务、外部动作或通用编排。

## 实现要求

1. 建立「契约条目 → 测试名/操作 → 证据 → 结果」验收矩阵，复核前阶段记录，不能照抄其通过声明。
2. 运行完整离线链路：创建、批准、定时、多周期、重试、补跑、编辑、暂停、取消、归档、重启与结果查看。
3. 故障注入包括写入失败、schema 升级失败、进程启动不明、会话未知、断网/限流、浏览器接管、超时、结果损坏和取消。
4. 复核去重、权限和自动发布隔离；普通手动研究、Topic FIFO、模型继承和报告发布不回归。
5. 生成 43,200 条一分钟实例夹具，覆盖成功/失败/跳过和代表性报告、来源、日志。注明每类数量、字节大小、是否清理日志，不能只用空壳实例冒充真实负载。
6. 在相同机器上记录新旧基线、样本次数、冷启动、列表/详情打开、保存、下一触发计算和主线程停顿。建议验收预算：列表/详情打开 p95 ≤ 500ms，单次保存 p95 ≤ 1s，交互主线程连续阻塞 ≤ 100ms；这些是待测目标，不是现有性能结论。
7. 如果 Store 全量保存达不到预算，先定位瓶颈，提出局部改进；需要改变持久化架构时单列设计影响并更新契约，不能临时关闭持久化或删除历史使测试通过。
8. 真实模型 smoke test 仅在明确授权后，用隔离工作区和已配置模型完成至少一个一般信息任务；同时覆盖示例所需时间上下文。报告事实仍需人工抽查，不能据一次生成成功宣称内容正确。
9. 更新 README、PRODUCT、DESIGN 和研究策略中已实现内容及限制；补跑、时间基准、暂停、恢复、权限、数据保留都应有用户可理解的说明。

## 验收矩阵最低要求

| 类别 | 必验行为 |
| --- | --- |
| 时间 | 四种周期、时区、DST、跨月年、前后跳、唤醒 |
| 记账 | 重复 tick、手动去重、事务回滚、启动前后崩溃、重复结果导入 |
| 生命周期 | 暂停/恢复、编辑、归档、项目不可用、工作区切换 |
| 执行 | 同一期重试、新一期隔离、有限排队、共享并发、过期、总超时 |
| 恢复 | 会话运行/完成/停止/未知；授权和快照不因重启丢失 |
| 权限 | 工具拒绝、接管阻塞、不自动发布、不改全局配置 |
| 数据 | 旧库升级/回滚、材料变化、报告/来源保留、日志清理边界 |
| UI | 完整操作链、错误修复入口、四组主题/尺寸、键盘和长中文 |
| 性能 | 30 天分钟级历史的生成方法、实测数据和预算结论 |

## 检查与完成标准

运行 `cargo test --quiet`、`--qa-automation`，以及 `--qa-concurrency`、`--qa-recovery`、`--qa-retries`、`--qa-topic-queue`、`--qa-batch`、`--qa-research`、`--qa-publishing`；涉及图标时运行 `python3 script/check_icons.py`。完整命令形式见共同任务入口。

- [ ] 每个必验类别有可复现证据，关键故障路径不是仅靠手工代码阅读。
- [ ] 回归通过；失败已解释并修复或明确列为未完成，不忽略失败命令。
- [ ] 性能预算有实际结果，未达到则不宣布达到分钟级长期使用验收。
- [ ] 真实 smoke test 标明实际执行或未执行及原因，不使用真实用户任务代替隔离测试。
- [ ] 文档准确区分强制校验、模型指令和未来能力。
- [ ] diff review 无越界重构、凭据、用户数据或意外生成物。
- [ ] 交付 `evidence/05-acceptance.md` 和简洁结果说明，列出发布阻塞项及已知限制。

全部必需离线验收通过才可声明首版代码验收完成；真实 smoke 未完成时应明确注明「真实执行链路尚未验证」。不得将这一阶段理解为提交、推送、发布或重启用户应用的授权。
