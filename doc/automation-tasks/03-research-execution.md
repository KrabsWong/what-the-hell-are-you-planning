# 阶段 3：研究执行适配

前置：阶段 2 通过，且阶段 0 的无人值守权限验证门槛通过。阅读 [共同约束](README.md)、[完整契约](../AUTOMATION_PLAN.md) 和现有研究策略文档。

## 范围

实现参数化计划生成/审批、每期研究步骤实例化、统一执行与结果关联、权限配置、自动发布隔离。使用现有 OpenCode 执行与研究校验；不添加外部动作、编排器或新的进程管理系统。

重点接入：`request_planning.rs`、研究数据/应用层、`opencode.rs`、`retries.rs`、`recovery.rs`、`report_publish.rs`。只在真实接入点修改，普通研究行为保持兼容。

## 实现要求

1. 创建时生成可重复使用的模板；批准前不执行。实例化只替换已知参数，不允许每期自由改变步骤或扩大工具权限。
2. 批准快照包含指令、步骤、依赖、有效模型、材料标识/内容签名及权限配置。全局模型改变不偷偷改变已启用自动化；用户修改自动化执行配置需新批准版本。
3. 建立独立批准来源，派发前复核签名和版本；不可伪造普通研究的审批字段或通过取消现有校验使自动化运行。
4. 每期新建工作目录、会话和浏览器 Space；同一期兼容重试可恢复。材料按批准快照提供，原件变化时阻止派发并要求更新批准，不默默读入新内容。
5. 注入计划时间、实际时间、时区、reference_time 和已解析窗口。普通研究仍以原 submitted_at 为基准。业务日期验证放执行步骤，缺数据应明确报告缺口。
6. 复用收集→分析→报告与依赖结果传递；保留输出结构校验、来源和材料引用。实例成功需要所需步骤和最终报告通过，不以进程 exit 0 直接宣布成功。
7. 错误分类接入有限步骤重试；实例层不再倍增重试。取消、权限/登录问题和未知状态不自动重试。实例总超时跨步骤、重试和重启持续生效。
8. 自动化结果保留本地；使用持久化来源关系从自动发布扫描排除，包括重启后、全局自动发布开启时。不得以标题约定作为唯一判断。
9. 更新 `doc/RESEARCH_WORKFLOW_STRATEGY.md` 中实际新增的自动化时间、批准、执行和限制语义，明确与普通研究区别；未实现的能力不得写成已支持。

## 验收标准

- [ ] fake planner 生成模板，批准后至少两个周期能独立完成；生成/保存草稿不启动步骤。
- [ ] 两期 session、目录、Space、结果均不混用；同一期重试保留原时间范围和模型快照。
- [ ] 固定日期用例证明「昨天」逐期变化、补跑和重试不漂移；未知交易日不被通用代码假定。
- [ ] 编辑内容/材料/执行配置使旧版待执行项失效；当前实例不被新版本修改。
- [ ] 明确拒绝未授权工具的执行层测试通过；浏览器接管进入需处理且不产生无限重试。
- [ ] 部分步骤失败、报告校验失败、超时、停止及重试耗尽得到准确实例状态。
- [ ] 全局自动发布开启仍不发布自动化结果，普通已授权发布不回归；fake Git 证明无额外 push。
- [ ] 普通研究审批、submitted_at、手动启动与恢复政策未被放宽。

验证：`cargo test --quiet`、`--qa-automation`、`--qa-research`、`--qa-retries`、`--qa-recovery`、`--qa-publishing`；默认全部为 fake 执行，不调用真实模型。交付 `evidence/03-research-execution.md`，包括权限和发布隔离证据。
