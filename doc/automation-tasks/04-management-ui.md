# 阶段 4：自动化管理界面

前置：阶段 3 通过。先读 [共同约束](README.md)、[完整契约](../AUTOMATION_PLAN.md)、`PRODUCT.md`、`DESIGN.md`、`doc/ICON_GUIDELINES.md`。

## 范围

增加侧栏自动化入口、列表、创建/编辑、详情、历史、结果和异常处理；连接已验证的应用层命令，不在 view 中重新实现调度或权限规则。不重设计品牌或相邻研究页面。

## 实现要求

1. 三步创建：任务与项目 → 周期/时区/三次预览 → 计划与授权摘要。草稿、生成计划、启用必须是不同操作；失败保留用户输入。
2. 展示实际有效模型、运行能力边界、补跑策略和需要应用运行的条件；高级设置承载允许延迟、总超时、日志保留等低频配置。
3. 列表显示名称、周期、下次时间、最近状态、未读结果。区分自动化是否启用与某次运行是否失败，不用单一状态覆盖两者。
4. 详情支持暂停、恢复、立即运行、停止本次、复制、编辑和归档。每个操作解释对当前及待执行实例的影响；禁用时给出原因。
5. 历史有界加载，区分计划和实际时间、重试和新周期、跳过与失败；查看最终报告为主，技术信息折叠。已读状态持久化。
6. 异常提供对应修复入口；如模型缺失指向模型设置，权限/浏览器接管显示具体原因，不只显示「失败」。
7. 实现已告知的日志清理设置和清理预览；不得删除报告、来源、材料或恢复/去重必需记录。
8. 自动化内部研究实体不淹没普通看板和任务树，提供从实例到相关步骤的明确导航。
9. 复用 controls、appearance 和现有组件。Lucide 图标必须语义正确、嵌入 AppIcons，图标按钮含 tooltip 和 accessible name。
10. 更新 PRODUCT.md、DESIGN.md 中已实现入口及交互约定，不覆盖用户原有修改。

## 验收标准

- [ ] 通过真实 UI 操作完成创建草稿、预览、生成/批准、启用、等待 fake 触发、查看结果、标记已读。
- [ ] UI 操作覆盖编辑重新批准、暂停/恢复、立即运行、停止本次、复制草稿、归档；验证数据库和 fake 启动事件，而不只检查截图。
- [ ] 存储失败不出现 Saved/Enabled 成功反馈；无效表单无法启用；后台结果不会覆盖用户正在编辑的草稿。
- [ ] 普通任务、自动化列表和内部步骤导航边界正确；切换页面输入和反馈按既有规则处理。
- [ ] 长中文标题、多行任务描述、长错误、空列表、大量历史和缺模型均可使用。
- [ ] 1440×920 与 1000×680，浅/深主题四组截图通过；Tab/Enter/Space、可见焦点和滚动可用。
- [ ] 不重启用户应用，全部通过隔离工作区和 fake CLI；图标无缺失。
