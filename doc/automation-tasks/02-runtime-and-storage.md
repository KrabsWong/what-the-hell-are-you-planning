# 阶段 2：持久化、调度与恢复

前置：阶段 1 通过；遵守 [共同约束](README.md) 和 [完整契约](../AUTOMATION_PLAN.md)。

## 范围

接入 Store、SQLite、工作区生命周期与统一队列，建立无真实模型的调度链路。新增最小运行协调模块和假执行器测试接缝；本阶段生产环境不启用真实自动化执行，不建设管理界面。

## 实现要求

1. 新增实体和版本迁移，通过统一 Storage 路径读写。旧数据没有自动化授权；新 schema 的备份、完整性检查、失败回滚与未知版本拒绝均需可测试。
2. 同一事务保存实例、快照/相关实体和下次时间；存储失败回滚相应内存状态。持久化完成后才派发，加载时验证去重关系。
3. 为调度增加空闲也会工作的 timer，支持可控时钟。按最近到期时间或有界低频周期唤醒；不得用执行 pump 的 80ms 循环永久轮询。
4. 等待系统唤醒后重新计算；工作区卸载/切换/退出时取消旧 timer，避免向新 Store 派发旧任务。恢复核验完成前不重复启动旧实例。
5. 使用独立的自动化并发池（默认 2，只统计 running 期次）和独立队列；不占用 Research 并发，也不进入 Research Topic FIFO，仅复用 session/目录/Space 资源锁。同一自动化最多一个活动和一个待执行实例。实现暂停、编辑、归档、过期和合并的队列移除，不只改变 UI 文案。
6. 使用可观测 fake runner（启动次数、实例键、输入快照、取消事件）测试完整调度。增加独立 `--qa-automation` 离线入口或其初始骨架，并明确当前覆盖范围。
7. 记录启动意图和可核验身份，处理保存后启动前及 spawn 结果不明的窗口；未知状态不能再次派发。状态仍在运行的实例必须占用执行资源。
8. 重试预算、截止时间、连续最终失败计数和未读状态必须持久化；本阶段先以 fake outcome 验证，不重写现有研究重试。

## 验收标准

- [ ] 无其他任务运行时，到期仍能产生并执行 fake 实例；重复 tick 只启动一次。
- [ ] 事务前失败不启动；事务后/启动前崩溃可恢复；启动后未知不盲目重放；重复结果导入不重复完成。
- [ ] 注入写入失败后实例、游标和内存队列一致；恢复保存后不会永久漏掉该触发点。
- [ ] 重启核验覆盖仍运行、已完成、确认停止、未知四种情况。
- [ ] 大量错过有界合并；过期项在派发前被拒绝；手动项不被定时替换。
- [ ] 暂停/编辑/归档取消未启动项；当前实例仍引用旧快照；关闭或切换工作区后没有旧 timer 继续派发。
- [ ] fake 自动化与手动研究使用互不影响的并发上限；降低任一上限不杀死已有工作，两种队列互不插队或互相阻塞。
- [ ] 从当前旧 schema 升级不丢任务/材料/报告/审批；备份可读，迁移失败保持原库完整。
- [ ] 明确测试项目不可用和全局存储错误时不派发。

验证：`cargo test --quiet`、新增 `--qa-automation`、现有 `--qa-concurrency` 和 `--qa-recovery`；涉及 Topic 排队时运行 `--qa-topic-queue`。只使用临时工作区和 fake CLI。交付 `evidence/02-runtime-and-storage.md` 及故障窗口到测试名的映射。
