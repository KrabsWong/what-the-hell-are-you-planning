# 阶段 0：执行边界与接入调查

前置：阅读 [共同执行约束](README.md) 和 [产品技术契约](../AUTOMATION_PLAN.md)。本阶段以只读调查为主，不实现业务功能。

## 范围

核实本地执行器权限、现有研究/队列/恢复/存储接口，给后续阶段可执行的接入设计。仅新增调查文档；必要的无副作用实验放临时隔离目录，不改全局配置或用户项目。

重点文件：`src/opencode.rs`、`src/app.rs`、`src/scheduler.rs`、`src/request_planning.rs`、`src/recovery.rs`、`src/retries.rs`、`src/sqlite_storage.rs`、`src/persistence.rs`、`src/report_publish.rs`、已有 QA。

## 实现要求

1. 记录当前代码基线、已有修改、实际 OpenCode 可执行文件和版本。用本地 help/配置和对应版本的官方资料核实能力，不写入凭据或整个敏感配置。
2. 说明如何按运行设置允许工具和写入范围，如何拒绝未授权工具，浏览器登录/接管如何停止；验证拒绝发生在执行层，而不是仅依赖提示词。实验不得实际发送消息、修改外部系统或调用付费模型，除非另有明确授权。
3. 如某项验证需要尚未授权的真实调用，标为未验证；权限门槛未通过不得放开无人值守执行。纯模型/存储阶段可继续，阶段 3 依赖该门槛。
4. 列出具体接入点：模板生成与审批、执行前复核、统一队列、实例聚合、恢复核验、发布排除、项目归档、普通列表过滤、应用关闭和工作区切换。
5. 说明 Store 的单写者所有权及事务边界，确定自动化实体如何保存、schema 如何升级、失败如何回滚内存状态。不要只建议另建数据库旁路写入。
6. 确定模板、实例、研究步骤之间的 ID/来源关系；明确如何保持现有普通研究审批和恢复不变。
7. 评估 IANA 时区支持和必要依赖；确定使用可注入时间源的方式。明确静态材料快照、模型继承在启用时解析后冻结的方式。
8. 把不能直接满足的契约列为具体阻塞项，给最小修复方案及影响；不能静默删掉权限限制或改成每期自由规划。

## 验收标准

- [ ] 每个接入点有真实文件、符号或行为依据，没有虚构接口。
- [ ] 权限结论区分已实测、文档支持但未实测、无法保证；有测试方法和结果。
- [ ] 确定启动前持久化、崩溃核验和自动发布排除方案。
- [ ] 确定窗口关闭/退出的实际行为，首版界面能准确告知运行边界。
- [ ] 无业务源码变更、无用户配置变更、无外部副作用。
- [ ] 交付 `evidence/00-feasibility.md`，明确阶段 1 可否开始、阶段 3 是否仍被权限问题阻塞。

验证：审查实际 diff 和调查引用；可运行只读版本/help 命令。无需为了文档调查运行完整测试，也不得声称未执行的实验通过。
