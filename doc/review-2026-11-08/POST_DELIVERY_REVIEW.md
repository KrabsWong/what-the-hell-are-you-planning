The previous claim that all common navigation and visual behavior had been adequately accepted was too broad. These commits correct ordinary daily workflows, not merely rare cross-products. The blanket T06/T07/T10/T11/T12/T19/T20 acceptance cannot be reused for these paths. Prior durability, execution and other unaffected evidence remains historical evidence for its actual source and scope.

The current changes are **source-reviewed corrections**, with stronger automated assertions visible in the code. Both commit messages report 743 passing tests and focused QA; those are author-reported results, not tests independently rerun in this documentation review. No native interaction or current-build performance measurement was performed here. In particular, `ce38de5` explicitly says native scrolling smoothness is not fully verified. The old release decision must not be read as current-build approval.

## Changes to the review method

1. Begin with the user's ordinary session: restart, inspect completed research, move between steps, resize the sidebar, read/regenerate and return. Automation correctness does not substitute for ordinary research acceptance.
2. Define destination and content identity before writing route tests. Include hydrated and lazy results, plus the transition between them.
3. Separate persistent product state from loading state and navigation intent. “No report” requires evidence that loading completed with no report.
4. Test interaction invariants, not a selected implementation: fixed identity, stable actions, flexible reader, contextual emphasis. A test that enforces our wrong design is negative evidence about the review process, not product quality.
5. Measure the executable users run and the actual event/draw path. Storage p95, headless input and native frame behavior are different evidence categories.
6. Narrow acceptance claims to observed scenarios. A full task inventory and many green tests are not proof of a full user-experience review.
