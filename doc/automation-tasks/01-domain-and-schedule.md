# 阶段 1：领域模型与时间计算

前置：阶段 0 接入报告可用；阅读 [共同约束](README.md) 和 [完整契约](../AUTOMATION_PLAN.md)。

## 范围

实现独立领域模型、状态规则、调度校验、下次时间及下三次预览、补跑决策。建议新增 `automation.rs`、`automation_schedule.rs` 和模块注册；必要时增加时区依赖。暂不接入 UI、Store 保存或真实进程。

## 实现要求

1. 用类型表达周期、触发来源、定义/实例状态和跳过原因；不要把 Cron 文本或自然语言作为执行规则。
2. 实现显式输入当前 UTC 时间的纯计算函数；同一函数服务预览和调度。不得在内部散落 `Local::now()`。
3. 按主文档定义间隔锚点、当地时间、IANA 时区、严格晚于启用时间、DST 规则和正整数/溢出校验。
4. 提供到期决策：最新可执行触发点、跳过范围及计数、下一游标；时间大幅前跳时计算有界，不逐周期循环创建对象。
5. 定义序列化结构、版本字段、不可变快照内容和触发唯一键；批准快照涵盖实际执行内容与配置。模型继承应在批准时解析为明确值。
6. 定义合法状态转换与防重入行为，包括暂停、恢复、编辑、归档、手动执行、自动合并、恢复未知和停止本次。实现可独立测试的规则，不把它们藏进按钮回调。
7. 定义时间上下文和前一自然日时间窗。业务日历未验证时不能伪造 `data_window`。

## 验收标准

- [ ] 10:03 启用每 5 分钟，未来三次为 10:08、10:13、10:18；一次任务运行时长不改变序列。
- [ ] 每日/每周跨月、跨年、闰日预期来自固定用例；空星期集、无效时区、零/负值及溢出被拒绝。
- [ ] 明确测试具有 DST 的时区：不存在时刻跳过、重复时刻仅一次；系统时区变化不改变已存规则。
- [ ] 补跑只选择最新且未过期的候选；用户暂停后恢复不补历史；回拨不退回已处理游标。
- [ ] 定时唯一键不因定义版本改变而变；手动键和定时键不同。
- [ ] 前一自然日按任务时区计算；重试输入同一 reference_time 时得到相同范围。
- [ ] 月级/年级错过范围的测试证明算法有界，无大量实例分配。
- [ ] 序列化往返及合法/非法状态转换测试通过；代码不触发任何进程或网络。

验证：运行新增模块测试及 `cargo test --quiet`，审查 diff。交付 `evidence/01-domain-and-schedule.md`，记录选用的时区依赖及理由。未接入持久化/界面必须如实说明。
